Expected verifier output
========================

Command
-------
    python code/verify_paper_numbers.py

Expected tail
-------------
    checks passed: 338, failed: 0
    report: data/results/paper_verify.json

What the 338 checks cover
-------------------------
1. Identity layer. Rounded means, deltas, sums, ratios and cost totals are
   re-derived from the artifact tables under data/results/ and compared with the
   values reported in the manuscript and the supplementary material.

2. Text layer. Table rows and reported tokens are rebuilt from the manuscript
   source and each one is required to appear in the text, so that a table and a
   sentence cannot drift apart.

3. Round-2 layer. A1-C1 cells and their transitivity, the exposure split, fold
   composition, the class-set table, the 43-class cross-instrument universe and
   the bel canto ceiling.

4. Round-3 layer. The arm table and its four rows, the thirteen-library
   inventory, the threshold-sensitivity sweep at 2, 3, 5 and 10 source
   recordings, the excluded-class profile, the cross-library duplicate count and
   the end-of-training losses. These are recomputed from
   data/results/library_inventory_and_convergence.json, the split files and the
   retained training logs rather than compared with a stored table.

5. Revision layer. The corrected bel canto recording-level baselines and
   contrasts are recomputed from
   data/results/human_review/corrected_recording_metrics.csv, and the
   provenance statements added in revision -- which libraries release audio,
   which archives were obtained, label-preserving canonical folding, the A2
   corpus share, the instrument group count and the multi-fold recording-level
   column -- are required to appear in the text.


6. Review-response layer. Section 6.4 states the two protocol contrasts as
   downward magnitudes with unsigned intervals ("lowers macro-F1 by 2.90 points
   (CI 0.32 to 5.66)"), matching the arrow directions in Figure 3, and one check
   requires the direction word "lowers macro-F1 by" to be present, so that a
   sign flip cannot pass unnoticed.

What the verifier does not do
-----------------------------
It reads the CSV and JSON artifacts, not the .npz predictions. The bootstrap
intervals are produced by the analysis scripts from the sealed predictions; the
verifier checks that the reported intervals match the stored analysis outputs,
it does not re-run the bootstrap. To re-derive the intervals, run:

    python code/round2_a1_minus_c1.py
    python code/round2_macro_denominator.py
    python code/sealed_eval_delta.py
    python code/round2_data_accounting.py

Each finishes in about a minute on one CPU core and reads only
runs/sealed_eval/.

The prose-claim layer
----------------------
A second gate, code/verify_claim_provenance.py, binds each quantitative prose
claim to the artifact cell it comes from through data/results/claim_ledger.csv.
Each ledger row fixes an artifact file, a row selector, a column, the printed
value, the prose phrase and the qualifier that must surround that phrase. The
gate fails if the cell no longer evaluates to the printed value, if the phrase
disappears from the named section, or if the qualifier no longer appears in the
same sentence. Expected output:

claims verified: 88, failed: 0

code/negtest_claim_provenance.py stages a temporary copy of the gate, reverts
three wordings to their earlier form and requires the corresponding claims to
fail, so the gate is checked against its own failure modes.

The quantifier layer
---------------------
A third gate, code/verify_quantifier_claims.py, binds the quantified claims in table
captions to the artifacts. A sentence whose numbers are right can still be wrong about
which arms or libraries it quantifies over: the bel canto note said "both reach 1.00"
in a table whose A0 arm averages 0.77, and the ratio caption said "0.991--1.001 of A0's
in every library" when the five ratios run from 0.9906 to 1.0014.

data/results/quantifier_ledger.csv holds ten rows: an id, the source file, a predicate
name, the sentence as printed and the expected values. The gate requires the sentence to
occur verbatim in the named file and the predicate to evaluate to the expected values on
the artifacts; inequality keys (_le, _ge) and rounding keys (_1dp, _2dp) are accepted.
It then walks every table float and requires each caption containing both, every, all,
each, none, neither, no or only to be covered by a ledger row or by an explicit waiver
in data/results/quantifier_waivers.csv. Two captions are waived. Figure captions are out
of scope. Expected output:

    quantifier claims: 10 in the ledger, 10 true and present, 0 failed
    table captions with a quantifier: 8 checked, 2 waived
    figure captions with a quantifier: 1, out of scope (drawings, not tables)

code/negtest_quantifier_claims.py breaks one artifact row, one ceiling score, one
sentence and one caption in turn and requires the corresponding failure, and requires
the clean tree to pass.

The reference list
------------------
There is no automated gate for the bibliography, because the check is against an
external record rather than an artifact in this repository. docs/reference-audit.md
carries the per-entry result: 20 entries were compared field by field with
api.crossref.org/works/{doi}, and the 9 without a registered DOI with the publisher
page (PMLR 37/70/97, JMLR 17, ISMIR 2017, SMC 2017/2020, OpenReview).

Two properties of the printed list are the style file's, not errors: numbering is
alphabetical because sn-basic.bst sorts in presort, and @incollection page ranges
print p rather than pp because bbl.incoll.pages is hard-coded to p.

To re-check a single entry:

    curl -s https://api.crossref.org/works/10.5334/tismir.194 | head -c 2000

Expected state of paper/refs.bib: 31 entries, no url field, every pages field written
with two ASCII hyphens, and 20 entries carrying a doi.
